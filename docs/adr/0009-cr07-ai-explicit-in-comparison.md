# ADR-07.6 — AI Processing Is Explicit in Comparison

**Status:** Accepted (2026-09-12, CR-07 audit + B1 slice)
**Source:** CR-07 §13 + §33, ADR-07.6

## Context

CR-07 §33 establishes that perceptual or generative transformations
cannot be hidden from the comparison context. The §13 AI-Aware
Comparison example is explicit:

> Version B contains AI Denoise, AI Detail Enhancement, and AI Super
> Resolution 2×. The user can then make an informed comparison.

The existing `Recipe.integrity` (`recipe.rs:77`) carries
`perceptual_models_used` + `seed_recorded` + per-model usage. The
existing `AiOperation::safety_classification` (`domain.rs:670`) carries
the three-way classification (Deterministic / Perceptual / Generative).

## Decision

`QualityAssessment::integrity_checks` carries the §12 astronomical
integrity findings **and** AI-specific disclosure fields. The
assessment is generated by aggregating the `AiOperation::safety_classification`
of every operation in the compared versions' lineage.

Concretely, the comparison UI surfaces:

- A badge per `ComparisonItem` indicating whether any operation in its
  lineage is Perceptual or Generative (`requires_disclosure()`).
- A list of AI operations in the lineage with model ID + version +
  hash + safety classification (read from the existing
  `AiOperation` rows).
- The `Recipe::integrity_label()` formatted string for at-a-glance
  consumption.

B1 does not yet codify the AI-disclosure surface in
`QualityAssessment` — the data is reachable via the foreign-key
chain. B5 (CR-08 Provenance + AI) will codify the AI-disclosure row
on `QualityAssessment`.

## Consequences

- **Positive:** The AI disclosure requirement (§13 acceptance
  criterion) is satisfied by aggregating existing `AiOperation` data;
  no parallel AI-provenance table is needed.
- **Positive:** The disclosure surface respects the existing
  `AiSafetyClassification::requires_disclosure()` method (CR-06 §17
  contract).
- **Negative:** Aggregating `AiOperation` rows per comparison query
  is N+1 unless a join is used. Performance optimization is deferred
  to R5 (which introduces `ProvenanceRecord` as a denormalized
  aggregate).
- **Negative:** The `QualityAssessment::integrity_checks` field is a
  free-form `Vec<IntegrityCheck>` rather than a typed enum — the
  consumer must know the integrity check vocabulary. B2 will codify
  the check kinds.

## Alternatives considered

- **New `ai_disclosure` aggregate table.** Deferred to R5 for
  denormalization.
- **Inline AI classification on `ComparisonItem`.** Rejected: the
  classification is per-version, not per-comparison-slot; storing it
  on `ComparisonItem` would duplicate data and require re-aggregation
  when the lineage updates.
